## SMP1: cores online, idle

- [x] Core identity by full affinity: `libcpu::smp::CoreAffinity` (Aff3, Aff2..Aff0 from the typed `MPIDR_EL1` fields, PSCI `CPU_ON` layout) replaces `core_id()`'s `MPIDR & 0x3`; `libboot`'s `_boot_cores` and chainboot's `_start` compare the full affinity with `libcpu::smp::BOOT_CORE_AFFINITY`. Host tests `just _host-test vesper-cpu smp` (Pi 3 Aff0, Pi 5 Aff1 numbering, Aff3); booted under QEMU by `_test-memory`, `_test-irq-rpi4` and `_test-chainboot`.
- [x] `libdevicetree::cpus`: `cpus()` lists the `device_type = "cpu"` children of `/cpus` in order (the logical index) with `reg` affinity, `enable-method` and `cpu-release-addr`; `psci()` reads the PSCI node (conduit, `CPU_ON` ID, 0.1 `cpu_on` property); `common_enable_method()` finds the method every CPU names. Host tests in `just _host-test vesper-devicetree devicetree` on the Pi 3, Pi 4 (spin table, 0xd8..0xf0) and Pi 5 (Aff1, PSCI 1.0 over SMC) trees.
- [x] Start-method ABI `libs/cpu-start` (`vesper-cpu-start`, workspace key `libcpu-start`): `CpuStartOps` (`abi_version`, `init(config)`, `start(cpu, mpidr, entry, context)`), `CpuStartConfig` (per-CPU affinity and release address, PSCI conduit and `CPU_ON` ID; `MAX_CPUS` 4), `StartStatus`, the `.cpu_start_enable_method` section and `cpu_start_export!`. Host tests `just _host-test vesper-cpu-start cpu_start` (layouts, status codes, the export macro).
- [x] Start-method components `drivers/cpu-start-spin-table` (plain store of the entry to the release word, `DC CVAC`, `dsb sy`, `sev`) and `drivers/cpu-start-psci` (`CPU_ON` over `SMC` or `HVC`, PSCI return codes mapped to `StartStatus`), position-independent with `linker/cpu-start.ld` (`just _build-cpu-start`): only `R_AARCH64_RELATIVE` relocations, no FP/SIMD, exclusive or LSE atomic instructions (checked with `rust-readobj`/`rust-objdump`). Host tests `just _host-test cpu-start-spin-table spin_table` and `just _host-test cpu-start-psci psci` (release words, affinity checks, `CPU_ON` arguments, every return code).
- [x] Kickstart bundles and selects the start method: `[[cpu_start]]` entries in `kernel/kickstart/image.toml`, `libimage-build::bundle_cpu_start` (a `PieKind` reader shared with `[[privileged]]`: `CPU_START_OPS`, `.cpu_start_enable_method`, `R_AARCH64_RELATIVE` only) into `embed::cpu_start::CPU_START`; `kernel/kickstart/src/cpu_start.rs` plans from `common_enable_method` and the PSCI node (no common method or no component: boot core only), loads the one component at its own physical address (droppable Kickstart memory), checks `ABI_VERSION` and calls `init` at EL2. `_build-privileged` builds the components for every Kickstart image. QEMU `raspi3b` and `raspi4b` (`_test-memory`, `_test-irq-rpi4`) pick `spin-table` and load it; the Pi 5's PSCI path is not run yet.
- [x] The firmware's low memory is left alone: `libdevicetree::DeviceTree::no_map_reserved_memory` (enabled `no-map` children of `/reserved-memory`, host-tested on the Pi 5's `atf@0` 0..0x80000 and the Pi 3/4 trees), reserved by Kickstart together with `/memreserve/` through `BootInfo::insert_reserved_region` (only pages no used region covers yet); Kickstart's init stack moved from `0x1000..0x80000` to right after the image (`linker/kickstart.ld`, `libcomponent-loader::paging::image_table_count`), chainboot's boot stack from below `0x80000` to after its relocated BSS (`bin/chainboot/src/link.ld`). Exercised by `_test-memory`, `_test-ppc`, `_test-sync`, `_test-irq-rpi4` and `_test-chainboot`; the Pi 5 reservation needs the board.
- [x] Per-core records and trap stacks: `nucleus::core_record::CoreRecord` (logical index, affinity, trap stack top; `current()` through `TPIDR_EL1`); `kernel/kickstart/src/cores.rs` plans the cores from `/cpus` (at most `MAX_CPUS`; boot core alone if `/cpus` does not list it), carves a 512 KiB trap stack per core and one run of records from accounted boot memory, and `paging::create_kernel_mapping` maps the stacks in slots after `__STACK_VIRT_BOTTOM` with guard pages (`paging::trap_stack_top`); `el_switch` sets the boot core's `TPIDR_EL1`, and `el1_entry` checks its record against `CoreAffinity::current()`. QEMU `raspi3b`/`raspi4b` (`_test-memory`, `_test-ppc`, `_test-sync`, `_test-irq`, `_test-irq-rpi4`, `_test-fault`): 4 cores, 4 stacks, core 0's record found at EL1.
- [x] Secondary entry: `libboot`'s `configure_el2` (the EL2 registers, factored out of `_startup_in_rust`); `kernel/kickstart/src/secondary.rs`'s `_secondary_entry` finds its slot of `SECONDARY_BOOT` by full affinity, runs at EL2 on its trap stack's physical top and calls `el_switch` with the shared tables and vectors and its own `SP_EL0`, `SP_EL1` and `TPIDR_EL1`; `secondary::publish` writes the table and cleans it to PoC. No BSS clear, lock, log or atomic on that path (checked in the disassembly); `el_switch` no longer logs. Not run until the release: the boot path is checked by `_test-memory`, `_test-ppc`, `_test-sync`, `_test-irq`, `_test-irq-rpi4`, `_test-fault` and `_test-chainboot`.
- [x] The cores are released: C12(a) (`el_switch` enters `EL1h` on the trap stack when given no execution stack); `secondary::release` publishes the table and calls `LoadedCpuStart::start` for every secondary just before Kickstart's drop to EL1; each secondary sets its bit in `ONLINE` (cacheable `fetch_or`) at EL1 and parks; `el1_entry` waits at most 1 s (`wait_online`). `libboot`'s EL3 → EL2 step is removed. QEMU `raspi3b`/`raspi4b` (`_test-memory`, `_test-ppc`, `_test-sync`, `_test-irq`, `_test-irq-rpi4`, `_test-fault`): "Released cores 0b1110", "Cores online 0b1110"; boards not run.
- [x] Secondary idle in the nucleus: `nucleus_secondary_idle` (exported in `.text.bootstrap`, `NUCLEUS_SECONDARY_IDLE_VIRT` through `libimage-build`) turns off `TTBR0` walks (`TCR_EL1.EPD0`, local TLB flush) and the core's physical and virtual timers, then waits on `wfi` with interrupts masked, touching no nucleus state; Kickstart's `secondary_el1` jumps there after setting its `ONLINE` bit, so no secondary runs Kickstart's memory any more. QEMU `raspi3b`/`raspi4b`: a temporary semihosting line showed all three secondaries arrive (`_test-memory`, `_test-irq-rpi4`); `_test-memory`, `_test-ppc`, `_test-sync`, `_test-irq`, `_test-irq-rpi4`, `_test-fault`, `_test-preempt`, `_test-dispatch-rpi4` pass with them idling; boards not run.
- [x] No set/way walk of shared caches while another core runs with caches on: the boot core runs `clean_invalidate_data_caches` before `secondary::release` (no longer in `el_switch`), each secondary only `libcpu::cache::clean_invalidate_l1_data_cache`; `ONLINE` sits alone in a 64-byte line, so a secondary's writeback cannot overwrite the boot core's caches-off stores after the release (`RELEASED`, `RUN_ENTRY`). Same QEMU tests as above pass; the hazard itself only shows on a board.
- [x] Test kernel `kernel/tests/smp-test` (`just _test-smp`, `_test-smp-rpi4`; `boot-smp-test` for the boards): each secondary stores the affinity it reads from `MPIDR_EL1` under its logical index before its `ONLINE` bit (`kickstart::smp`); the test checks every released core is online (QEMU: `0b1110`), each affinity is distinct from the others and the boot core's, and, with Kickstart's `smp_test` feature, a coherency round where all four cores add 100 000 each to one cacheable counter (400 000 of 400 000). A wrong expectation was checked to fail the run (exit 1).
- [x] C13(a): `libkernel-state` reduced to the init-phase flag `libkernel_state::is_init()` that `InitStateLock::write` checks; the `Init → SingleCoreMain → MultiCoreMain` state machine, its transition and Kickstart's commented-out call are removed. `_clippy-pre-push`; `_test-smp`, `_test-memory`, `_test-irq-rpi4`, `_test-fault`.

## SMP2: one kernel lock and per-core state

- [x] Per-core state in the per-core record (`kernel/nucleus/src/objects/core_record.rs`, `nucleus::core_record` re-exports it): `CoreState` (`current_thread`, `current_since_ticks`, `dispatched`, `dispatch_next`, `preempt_requested`, `interrupt_ticks`, `idle_ticks`, `fp_totals`) out of `Nucleus` into `CoreRecord::state`, reached through `Nucleus::this_core` (`ThisCore`: the `TPIDR_EL1` record, or a fixture's state in the nucleus tests); the statics `IDLING`, `timer::PROGRAMMED` and the FP entry guard's `EXIT_FP_OPEN`/`TOGGLES` are the record's `idling`, `programmed_deadline`, `fp_exit_open` and `fp_entry_toggles`; Kickstart writes records with `CoreRecord::new`. The totals are the publishing core's own (C11(a)); only core 0 has a root Scheduler yet. `just test` (every QEMU kernel, the nucleus suites, host tests) and `_cross-clippy` `qemu` and `qemu,debug_kernel`.
