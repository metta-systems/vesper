# Capabilities completed

Short markers of what is done, grouped by plan phase. Each line says what exists and where it is exercised. Rationale and details are in the [contract](capabilities-contract.md); the history of how each piece landed is in version control.

## Object-types review

- [x] `Domain` split into the arch `AddressSpace` (translation root, ASID, protection boundary) and the core `Thread` (execution, scheduling, pending state); catalogue renumbered, docs regenerated.
- [x] Reserved `ASID` kind replaced by `ASIDControl` (arch index 4, `0x84`); ASIDs are values bound to an AddressSpace.

## Phase 1 — Confirm contracts and support boundaries

- [x] Status matrix confirmed against dispatch; it lives as the catalogue in `doc/object_types/README.md`.
- [x] Ordinary-operation schema template (ID, widths, slot scope, authority, result, blocking, ownership, failure) recorded in the contract.

## Phase 2 — One shared, testable ABI

- [x] Host ABI tests (`just _test-object-host`, `host-tests` feature) and host lint (`just _clippy-object-host`) wired into `just test`/`just clippy`; the ABI is tested natively on its own architecture.
- [x] One canonical `CoreType`/`ArchType` catalogue (`0x80` arch bit, category-local indices distinct from wire IDs) with exhaustive literal tests over all 256 bytes.
- [x] Full-width operation decoding for every kind (unassigned IDs and high-bit aliases rejected); checked narrowing of slots, sizes and kinds; nonzero unused words rejected.
- [x] `Rights::from_wire` rejects undefined rights bits before authority checks in CopyDerive, Retype and `Frame.Map` (closed a Retype hole that minted bits 6–7).
- [x] Shared status codes 0–36 with one encoder/decoder pair; anything unrepresentable decodes losslessly as `UnknownResponse`; no per-family error spaces.
- [x] Operation schemas and unassigned IDs recorded; strict wire-argument convention (unused words zero).
- [x] User-visible records (`PpcResult`, `ResultSpill`, `ExportRecord`) carry const layout assertions.
- [x] Current-consumer compatibility policy: rebuild everything together; unsupported operations show up as errors.

## Phase 3 — Repair the active syscall/console path

- [x] DebugConsole gated behind `debug_kernel` (handler, grant, boot use); its results are propagated and its wrapper no longer prints.
- [x] Hardware debugging aid: in a `debug_kernel` kernel every component Kickstart loads gets a `WRITE` console key (`DriverInit::debug_console`, slot 15) its panic handler prints on, and Write reads caller-virtual memory checked by `AT` at the caller's level and prints on the board UART outside QEMU (`kernel/nucleus/src/objects/debug_console.rs`, `kernel/nucleus/src/board_console.rs`, `userspace/runtime`); exercised by the nucleus `debug_console` suite, `capability-test` and `ppc-test`, and on the Raspberry Pi 5 by board-test's log probe (`just boot-board-test debug_kernel`); EL0 bytes are read with `LDTRB` because the Pi 5's Cortex-A76 sets PAN on exception entry.
- [x] Explicit caller context: an absent current Thread is rejected, never defaulted to Thread zero.
- [x] Entry checks the exception class and origin; non-SVC EL0 exceptions go to fault delivery; the SVC immediate is ignored.
- [x] No panicking register conversions on the entry path.
- [x] Register preservation: an ordinary invocation writes only `x0..x2`; `x3..x30`, SP and NZCV survive success, rejection and blocking resume (`libkicktest::registers`, `capability-test`, `sync-test`).
- [x] Every wrapper returns kernel results through `decode_syscall_result`; unimplemented operations fail with `InvalidOperation`.

## Phase 4 — Capability storage and Thread lifetime

- [x] Packed 64-bit keys (32-bit incarnation, 32-bit table-relative address); commit-only incarnation advance, retained counters, slot-local exhaustion (`KeySlotExhausted`); statuses 26–28 with reasons and operand index; actual-key bootstrap handoff.
- [x] Guarded key space: variable-size KeyTables (`size_bits` 1–20), per-table guard in the KeyTable capability, `SELF_KEYTABLE` as the guard source, `GuardMismatch` rejection.
- [x] Guarded kernel access: owning `Access` context, short-lived guards, alias-safe pair resolution, single-core execution, no lifetime-erasing casts; `KeyEntry` is kernel-private.
- [x] KeyTable invariants: no counted null inserts, checked bounds, failed insertion returns ownership.
- [x] KeyTable CopyDerive/Move/Delete with separate `DERIVE`/`REMOVE`/`INSTALL` rights, incarnation-checked selectors, vacant destinations, atomic cross-table updates and Move rollback (`test-key-table`).
- [x] Pooled objects carry generation-checked identities (`ObjectPool`, one variable-size carve per pool from the boot Untyped).
- [x] A capability naming a no-longer-live pooled object fails with `InconsistentKey`/`ObjectRetired` on its key (`IdentityError::for_key`); exercised by `sync-test`, `memory-test`, the Call fixture in `test-debug-console` and the `ObjectPool` unit tests.
- [x] KeyTable Delete removes entries naming retired Threads and AddressSpaces without resolving the object; the deleted key then reports `CapabilityInvalidated` (`sync-test`, `memory-test`).
- [x] The current Thread is an incarnation-checked identity (`Nucleus::current_thread: Option<ObjectId>`, read through `current_thread_id`/`current_thread_ref`); stale generations select no Thread, table or legacy `DcbPages` record (`test-debug-console`).
- [x] `Thread.Retire` (op 4, `RETIRE`) cancels the Thread's pending waits and retires the carved Thread; `AddressSpace.Retire` (op 1) invalidates its ASID and releases it (`sync-test`, `memory-test`).
- [x] The run queue holds incarnation-checked carved Thread identities, linked through the Threads and validated on every push and pop (`kernel/nucleus/src/objects/sched.rs`; nucleus `sched` tests).
- [x] Inert-nucleus boot: Kickstart carves the `Nucleus`, the boot Thread/AddressSpace and table, and installs the boot grants.
- [x] Scheduler, IRQControl and IRQHandler registered as core wire kinds (`5`, `10`, `11`) with no handlers; there is no Brand kind (`libs/object` catalogue tests).

- [x] KeyTable retirement identity: a KeyTable is a `Carved<KeyTable>` named by its `CarvedId` in `KeyTablePayload`, `KeyTableBinding` and `CallerTable` (`kernel/nucleus/src/objects/key_table.rs`); every table resolution validates the header (`Access::resolve_caller_table`, `TableCap::resolve`), and a retired bound table fails syscall entry with `InconsistentKey`/`ObjectRetired`. Exercised by `retired_table_rejects_capabilities_in_every_table` (`kernel/nucleus/tests/key_table.rs`) and `retired_bound_table_rejects_every_invocation_from_its_address_space` (`kernel/nucleus/tests/debug_console.rs`).

## Phase 5 — Memory and safe reclamation

- [x] Transactional batch `Untyped.Retype` (validate → reserve → initialize → install → commit watermark): only the unused watermark range, absolute alignment, representable extents, device sources rejected except for Untyped splits (`test-untyped`).
- [x] Retype creates KeyTables, Frames (12/21/30-bit), PageTables, Notifications, EventCounts and Untyped children; Frames and PageTables are zeroed before they become visible.
- [x] Kernel object pools sized at creation from one watermark carve (`ObjectPool::carve`, `RegionPayload::reserve`).

## Phase 6 — Deferred completion and IPC

- [x] Pending-invocation records with non-wrapping generations, a single terminal transition, bounded FIFO wait queues, and teardown cancellation.
- [x] Blocking waits park a Thread-resident continuation; one kernel stack per core; resume rewrites the transient frame.
- [x] Notification Signal/Await/Poll (`SEND`/`RECV`, badge or argument bits, one consumer) and EventCount Advance/Await/Read (overflow as `CounterOverflow`, broadcast wakeups), with wrappers and host tests (`test-sync`).
- [x] Kernel-mediated release/acquire for payload publication.
- [x] PPC: `AddressSpace.CreateInvocation` (op 3) with stack extent and headroom, `InvalidStack` 1–12; `Invocation.Call` with `x9` SP, depth-16 Thread-resident stack, `NestingDepth`; `Thread.Return` on `CurrentReturnOnly`, Return faults; register scrubbing and status inheritance (`test-ppc`).
- [x] One KeyTable per AddressSpace, bound at provisioning; source and Bounce run on independent roots and ASIDs.
- [x] Userspace PPC: `ppc_call`/`ppc_return` wrappers, `ppc_export!`, `export::complete_export`, `UnexpectedReturn` (34), `vesper_thread_return_fault` handoff.
- [x] Architectural state: `TPIDR_EL0` per Thread and scrubbed across PPC; `TPIDRRO_EL0`, `CNTKCTL_EL1`, `MDSCR_EL1`, `PMUSERENR_EL0` set at boot; FP/SIMD trapped at EL0 and EL1 (`test-fp-trap`, `just _audit-fp-simd`).
- [x] Per-call timestamp in each continuation record (charging inert until a clock exists).
- [x] Queued-rendezvous endpoint example as a userspace composition over Invocation and Notification/EventCount (`test-endpoint`).
- [x] Fault delivery: synchronous upcall into `KeySlot::FAULT_HANDLER`, retry/skip/terminate, unhandled faults park the Thread as `Faulted` (`test-fault`).

## Carved objects and device memory

Time and scheduling work is in [`scheduling-completed.md`](scheduling-completed.md).

- [x] Carved-object identity (header with kind, state and generation; identity = kind, kernel address, generation): Notification, EventCount and Time are carved from the invoking Untyped, their boot pools are gone, the boot Time is carved from the boot Untyped, and pending records name the object they wait on (`kernel/nucleus/src/objects/carved.rs`; nucleus `carved`, `nucleus` and `untyped` tests, `sync-test`, `endpoint-test`, `fault-test`, `fp-trap-test`).
- [x] Threads are carved objects: the boot, idle and trusted fixture Threads come from the boot Untyped (`kickstart::bootstrap::carve_boot_object`), the runnable queue links through the Threads, Thread capabilities and pending records name Threads by carved identity, and `Thread.Retire` bumps the generation (`kernel/nucleus/src/objects/{thread,sched}.rs`; nucleus `sched`, `thread`, `nucleus`, `debug_console` and `key_table` tests, every boot test kernel).
- [x] AddressSpaces and PageTable metadata are carved objects: their boot pools are gone (only the ASID-pool pool remains); `Untyped.Retype` of `count` PageTables carves the tables and then their metadata records from the invoking Untyped; the boot AddressSpace and the Bounce/fixture AddressSpaces are carved from the boot Untyped (`libcomponent_loader::carve`); capabilities, Frame mapping records, Invocations, Thread and continuation records name an AddressSpace by carved identity (64-byte `KeyEntry` with a 56-byte payload); `AddressSpace.Retire` bumps the generation (`kernel/nucleus/src/api/untyped.rs`, `objects/arch/{address_space,page_table}.rs`; nucleus `untyped`, `key_table` and `debug_console` suites, `memory-test` record placement, Untyped charge and retirement checks, every boot test kernel).
- [x] `Untyped.Retype` creates inert, unbound AddressSpaces; `AddressSpace.Bind` (op 2, `MAP` on the AddressSpace, `INSTALL` on the KeyTable) binds a self-naming KeyTable once, installing the `THREAD_RETURN` sentinel, and a table may serve several AddressSpaces; Activate, CreateInvocation, `Scheduler.ConfigureThread` and Calls into an unbound AddressSpace fail with `NotBound` (status 40) while PageTable/Frame mapping and `ASIDPool.Assign` work; the component loader creates component AddressSpaces through Retype and Bind (`kernel/nucleus/src/api/arch/address_space.rs`, `libs/object/src/address_space.rs`, `libs/component-loader/src/component.rs`; host ABI tests, `memory-test` `address_space_bind`, every component-loading test kernel).
- [x] `InvalidSelfReference` (status 41; `x1` the self slot, `InvalidSelfReference::KeyTableKey(4)`; `x2` the key that led to the table) is reported at syscall entry, by `AddressSpace.Bind` and by `CreateInvocation's` placement check for a table whose `SELF_KEYTABLE` capability does not name it (a `CallWithKey` caller gets `NotBound` instead), replacing the provisional `InconsistentKey`/`CapabilityInvalidated` (`libs/object/src/syscall_status.rs`, `objects/invocation.rs`, `api/arch/address_space.rs`; host ABI tests, nucleus `debug_console` suite, `memory-test`).
- [x] Retired objects are held until cleanup: no retirable kind is pooled, and a retired Thread's or AddressSpace's carved memory is never re-carved (`memory-test`, `sync-test`).
- [x] Device Frames: Retype carves Frames from a device Untyped without zeroing them, and `Frame.Map` installs them as Device-nGnRnE memory, never executable (nucleus `untyped` and `page_table` tests).
- [x] Kickstart hands out device Untypeds for the enabled device-tree ranges (page-rounded, merged, aligned power-of-two blocks, kernel-owned pages withheld) in boot slots from 160, recording the range in `BOOT_INFO` (`kickstart::bootstrap::install_device_untypeds`; `memory-test` checks none overlaps the interrupt controller and maps and reads the PL011 through one).
- [x] The ARM local interrupt block (`brcm,bcm2836-l1-intc`) is withheld from device memory on every board (`kickstart::privileged::WITHHELD`; `libkicktest::devices::assert_device_untypeds_avoid_the_kernel` in `preempt-test` on rpi3 and rpi4 and in `memory-test`).

## Interrupt delivery

- [x] IRQHandler delivery to an EventCount: reviewed and deemed unusable (2026-10-14). The kernel only knows which line fired, so a Notification is enough; EventCount-based counting (bytes received, xbuf queue entries) is done by the interrupt-handling Thread with ordinary `EventCount.Advance` ([contract](capabilities-contract.md#irq-delivery)).
- [x] Nucleus IRQ table carved by Kickstart from the boot Untyped, sized by the component's line count; delivery signals a bound line's Notification with its badge, masks the line and ends the interrupt, and masks and ends unbound lines (`kernel/nucleus/src/objects/irq.rs`, `api::irq::deliver`).
- [x] `IRQControl.Issue` (controller index and specifier, trigger from the specifier through `libirqchip` ABI 2 `xlate`, one live handler per line, timer line `IRQ_LINE_ACTIVE`) and `IRQHandler.SetNotification`/`Clear`/`Ack`/`Retire`; IRQControl at `KeySlot::IRQ_CONTROL`; controller order in `BOOT_INFO` (`kernel/nucleus/src/api/irq.rs`, `libs/object/src/irq.rs`; host ABI tests, nucleus `irq_tests` against a fake component, `irq-test` EL0 receiver over three virtual-timer interrupts on rpi3 and rpi4).
- [x] `libdevicetree::interrupts`: generic timer, root controller, controller listing and per-node interrupts (`interrupts` with inherited `interrupt-parent`, or `interrupts-extended`) resolved to controller phandle and cells; Kickstart plans its controllers with it and records the DTB location in `BOOT_INFO` (`libkicktest::devices::device_tree` reads it again at EL1; `devicetree` host tests, `irq-test` takes its timer specifiers from the device tree).
- [x] `libcomponent-loader`: boot-table keys, the builder, component AddressSpaces and the EL0 image loader, shared by Kickstart and the test kernels (`libs/component-loader`; every e2e test kernel).
- [x] Driver matching: `driver_compatible!` (`.driver_compatible` section) and the `DriverInit` init page (`libs/device-driver`), `[[driver]]` manifest entries with budget and memory (`DriverImage`), and `kickstart::drivers::load_drivers` loading one instance per enabled matching node with page-sized device Untypeds or shared device Frame copies, IRQHandlers bound to one Notification, a RAM Untyped, a Time and a started Thread (`driver-test` probe driver on rpi3 and rpi4).
- [x] PL011 EL0 driver component (`drivers/uart-pl011`) carving its device Frame and serving a client's `libserial-channel` transmit and receive IO channels (`libio-channel`: Rbufs-style IO_Rec packets over an fbuf data area, client EventCounts) from an interrupt Thread and a transmit Thread; drivers declare further Threads with `driver_threads!` and share a driver-private EventCount from `DriverInit`; the GICv2 component routes SPIs to the booting core (`io_channel`, `serial_channel`, `pl011` and `gicv2` host tests; `uart-test` loopback on rpi3 and rpi4).
- [x] Kickstart's real boot path loads the bundled drivers (`[[driver]]` in `kernel/kickstart/image.toml`, `just _build-drivers`) and parks the boot Thread.

## Later capability work

- [x] `Invocation.CallWithKey` (op 1): lends one `Lend`-carrying key (`KeyTable`, `Frame`, `DebugConsole`) for the call in `x8`; the borrowed entry is placed in the first vacant slot of the exporter's placement window (`AddressSpace.CreateInvocation` `x8`), marked `LENT` (never a CopyDerive/Move source, lendable onward), and removed by `Thread.Return`, `Thread.Retire` and fault parking; statuses `KeyNotAccepted` (38) and `NoPlacementSlot` (39); key diagnostics report operand 8. Kernel in `kernel/nucleus/src/objects/invocation.rs` and `api/invocation.rs`; ABI and wrappers in `libs/object` (`InvocationKey::call_with_key`, `PlacementWindow`) and `libs/syscall` (`ppc_call_with_key`); exercised by the nucleus `invocation_call` and `key_table` suites and end to end by `ppc-test`, where a Bounce target installs a key into the lender's table through the borrowed one.
- [x] The Domain and DCB code is gone: `libs/object/src/domain.rs` (`DomainId`, `DomainState`, `DomainControlBlock`, `DcbPage`, `DcbView`), the nucleus `DcbPages`, its scheduler hooks and the KeyTable `owner` field. `ThreadKey` carries only its key; its state observations wait for the scheduler-shared records. The Kickstart init sketch (`kernel/kickstart/src/main.rs`) names components.
- [x] `InvalidDomain` split into `InvalidThread` (3: missing or stale Thread, or a capability entry from a non-execution stack) and `InvalidAddressSpace` (4: stale AddressSpace), with the later statuses renumbered (`libs/object/src/syscall_status.rs`). Exercised by `libs/object/tests/support/cap_error.rs` (literal baseline), `kernel/nucleus/tests/debug_console.rs` (stale caller AddressSpace) and `kernel/nucleus/tests/support/resume.rs`.
- [x] `WaitSet` (core kind 9, `0x09`): a kernel object that waits on up to 8 Notifications and EventCounts, with `AddMember`, `UpdateMember`, `RemoveMember` and a level-triggered, non-consuming `Await` that returns the mask of ready slots; a listed Notification refuses direct waits (`Watched`, status 44) and a retired member is an error (`MemberRetired`, status 45) (`libs/object/src/wait_set.rs`, `kernel/nucleus/src/objects/wait_set.rs`, `kernel/nucleus/src/api/wait_set.rs`, `Nucleus::wake_wait_sets` after Signal, Advance, interrupt delivery and membership changes). Exercised by the ABI tests (`just _test-object-host`), the nucleus unit and fixture tests (`just _test-device`) and the blocking round in `sync-test` (`just _test-sync`).
- [x] Badges on derive: a 64-bit badge in the 16-byte `KeyEntry` header with a 48-byte payload, the `BADGE` right (`0x80`), `KeyTable.CopyDerive` setting a badge once on an unbadged `Invocation` or `Notification` (`x6`; `AlreadyBadged`, status 46) and accepting those kinds with narrowing rights, and the badge delivered in `x1` of the PPC entry (`ppc_export!`, the Meddle runtime and the generated `enter(badge)`). Exercised by the nucleus key-table tests (`just _test-device`), `ppc-test` (`just _test-ppc`: a minted badge reaches the compiled export) and `sync-test` (`just _test-sync`: a badged Notification signals its badge).
- [x] Stack pools: `AddressSpace.CreateStackPool` (op 4) and `DestroyStackPool` (op 5) make and destroy up to 16 pools per AddressSpace (1 to 64 stacks, a 64-bit free mask, a slot and generation handle); `CreateInvocation` takes the pool handle in `x5`; `Call` and `CallWithKey` take the lowest free stack (`NoFreeStack`, status 47, `StaleGeneration`), `Thread.Return`, `Thread.Retire` and fault parking give it back, and the extent form and the `x9` SP argument are gone from the kernel, `libs/object`, `libs/meddle-runtime`, the generated clients, `libs/device-driver` (`Masters` keeps one master per function on `DriverInit::export_pool`), `libs/component-loader` (`Builder::stack_pool`), Kickstart (one pool of 16 four-page stacks with guard pages per exporting driver) and every test kernel (`kernel/nucleus/src/objects/stack_pool.rs`, `libs/object/src/stack_pool.rs`). Exercised by the pool unit tests and `invocation_call` fixtures (`just _test-device`), the ABI tests (`just _test-object-host`) and `ppc-test`, `endpoint-test`, `fault-test`, `fp-trap-test`, `memory-test`, `mailbox-test`, `usb-test`, `usb-core-test`.
- [x] The legacy kernel-era driver stack `libs/platform` is gone. `bin/chainboot` has its own `platform` module (`bin/chainboot/src/platform`): the PL011 on GPIO14/15, polled, with divisors from the UART clock the firmware reports through the mailbox; the mailbox property channel; the activity LED (blinking while it waits for the host and while the kernel arrives, off before the jump); the board constants. `BOOT_CORE_ID` is in `libboot`. Exercised by `just _test-chainboot` and by loading a kernel through the hardware chainboot image under QEMU with `chainofcommand`.
- [x] `libs/driver` and the QEMU device-test console path in `libmachine` (`drivers::qemu_bring_up_console`) are gone with `libs/platform`.
- [x] Chainboot runs on a Raspberry Pi 3B: the logger is set with `libconsole::init_logger_racy` (the atomic swap of `init_logger` never completes with the MMU off), the UART clock is started and read through the mailbox, bring-up reports on the LED (flash codes, then blinking), the banner names the model from the device tree, and waits on the UART are bounded. `bin/chainboot` has an opt-in `mmu` feature (`platform::mmu`, `just build-chainboot rpi3 mmu` makes `chainboot-rpi3-mmu.bin`): a flat identity map with RAM as Normal non-cacheable memory and peripherals as Device memory, on while chainboot runs and off before the kernel. - [x] `just build-chainboot` ends with an audit (`_audit-chainboot-exclusives`) that fails when the chainboot ELF holds a load/store-exclusive or an LSE atomic: with the data cache off the Pi's cores never complete them, and QEMU does. Exercised by the four chainboot builds (rpi3, rpi3 `mmu`, rpi3 `qemu`, rpi4), which pass, and by `nucleus`, `usb-core` and a chainboot build with the old `init_logger()` call, which it rejects.
- [x] Six-word `Thread.Return` (C1(b)): the payload `r0..r5` in `x2..x7` resumes in the caller's `x1..x6` (`PreparedReturn`, `kernel/nucleus/src/objects/invocation.rs`); `ppc_call`/`ppc_call_with_key` return six words, `ppc_return` and `return_from_invocation` take six, `PpcResult` is six words (`PpcResult::pair`) and `vesper_thread_return_fault` gets them by reference. Exercised by the `invocation_call` Return tests (`just _test-debug-console`), the ABI tests (`just _test-object-host`) and `ppc-test` (`just _test-ppc`: raw and library Returns, the clobber target's six words).
