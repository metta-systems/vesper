# Components: completed work

One line per finished item of [components-implementation-plan.md](components-implementation-plan.md).

- [x] Meddle IDL front end and Rust stub generator (`libs/meddle`, CLI `bin/meddler`), runtime support (`libs/meddle-runtime`); `mailbox_v1` generates the `mailbox` interface crate and the `mailbox-client` crate, built against the stub `mailbox` component; tested by `just _test-meddle`, linted by `just _clippy-meddle`.
- [x] Kickstart wires `interfaces/imports.if`: each `uses ... via <property>` binds to the driver instance the client node's property links to, with one Invocation per function and one exporter stack per client, delivered in `DriverInit::imports` with the exporter's Return key in `DriverInit::return_key`; `just _test-driver` and `just _test-driver-rpi4` exercise calls and an exception from `uart1` into `aux`.
- [x] Mailbox loading: `uses ... via first, second` link chains (Meddle, image tables, Kickstart), device Frames minted for kernel-owned pages of drivers on `privileged::SHARES_KERNEL_PAGES` (the Raspberry Pi 3 mailbox), and the `mailbox` driver in the boot image; `just _test-mailbox` and `just _test-mailbox-rpi4` load it and call it from the power node through `firmware, mboxes`.
- [x] Mailbox request path: typed `mailbox_v1` functions build property-tag buffers in a bounce page carved from the driver's memory, reached at its `dma-ranges` bus address (`DriverInit::memory_bus`, `libdevicetree::dma_address`), cleaned and invalidated with the Frame cache operations; one request in flight through `turns`/`replies` EventCounts, replies taken by the interrupt Thread; `just _test-mailbox` and `just _test-mailbox-rpi4` check QEMU's board revision, serial, UART clock and power state.
- [x] Data areas for Meddle interfaces: `data <bytes>;` in an interface, one area per (client, exporter) pair created and mapped by Kickstart's import wiring at one address in both (`DATA_WINDOW_VA`, `ImportRecord::area_*`, `DriverInit::areas`, `Client::data_area`), the exporter finding its caller's area by the badge of the key it was called through (`area_for_badge`); `mailbox_v1.property` copies a client's buffer into the bounce page, checks it against a tag whitelist (`mailbox_impl::check_request`) and writes the firmware's answer back; `just _test-mailbox` and `just _test-mailbox-rpi4` check an answered request, refused tags, malformed buffers and references outside the area; `just _test-platform-host` covers the whitelist and the area lookup.
- [x] `power` and `fb` components replace the old kernel-era drivers: `power` (`power_v1`: `devices_off`, `halt`, `reset`) drives the power management node's reset registers and powers the firmware's devices off through the mailbox; `fb` (`fb_v1`: `configure`, `address`, `size`, `pixel_order`) configures the display through `mailbox_v1.property`; both are in the boot image, wired to the mailbox by `compatible` and `firmware, mboxes` links; `just _test-mailbox` and `just _test-mailbox-rpi4` have a client configure a 640 by 480 framebuffer, power the devices off, and find `halt` and `reset` not granted to it; `just _test-platform-host` covers the register values and property buffers.
- [x] Video memory for `fb`: Kickstart infers the `VideoCore` memory gap from the memory map and installs it as device Untypeds ahead of the register ones (`video_untypeds`); a driver with `video_memory = true` receives them in `DriverInit::video`; `fb` refuses a framebuffer outside them; `just _test-mailbox` and `just _test-mailbox-rpi4` check the blocks span the firmware's range and that the framebuffer lies inside.
- [x] Meddle `lends` clause: `lends (key_table name)` or `lends (frame name)` on a function of a `local` interface, with `placement <slots>;` (1 to 8) on the interface (`libs/meddle`: lexer, parser, checks, generator, type code; `libs/meddle-runtime`: `Binding::call_with_key`, `export_function_with_key!`). The generated client takes the lent key first as `&KeyTableKey`/`&FrameKey` and calls `InvocationKey::call_with_key`; the generated server entry passes the borrowed key first to the trait method. `Import::placement_slots` and `Import::lends` reach Kickstart through the image tables; Kickstart reserves each (client, exporter) pair's window in the exporter's table once and creates a lending function's Invocation with it. Exercised by `libs/meddle/tests/meddle.rs` and end to end by `driver-test` (`echo_v1::frame_base`, lent Frames between probe instances).
- [x] Meddle resource keys (`installs`, `badged`): `installs (<interface>)` on a `lends (key_table ...)` function with a `card32 first_slot` parameter, and `badged;` on the installed `local` interface so its server functions get the key's badge first (`libs/meddle`: lexer, parser, checks, type code, summary, `<interface>_entries()` in the export macro, `FUNCTION_COUNT`, client `Bindings::from_installed`). Exporters keep per-(client, function) masters with `libdevice_driver::Masters` (created lazily from the exporter's own `AddressSpace` key, badged `CALL`-only copies derived into the lent table; `DataArea::write_u64s` returns the key values). Exercised by `libs/meddle/tests/meddle.rs`, `libs/device-driver/tests/masters.rs` and end to end by `usb-test` (`usb_hcd_v1.open_pipe` installs the `pipe_v1` keys; the client copies, closes through a copy and checks that stale keys fail).
- [x] `fb_v1.frames` (`frames(first_slot) lends (key_table into)`, `placement 1;`): `fb` hands the Frames that cover the configured framebuffer's pages (2 MiB Frames on their alignment inside the buffer, 4 KiB for the rest, `fb_impl::FramePlan`) to the caller by carving them from its video-memory Untypeds straight into the table the caller lends, in address order from `first_slot`; the memory below the buffer in its block is first carved into Untypeds that stay in `fb`'s own table (`fb_impl::skip_chunks`), since Retype only allocates at an Untyped's watermark. Exceptions `not_configured`, `out_of_video_memory`, `already_handed_out`, `install_failed`. Exercised by `drivers/fb/tests/requests.rs` (planning, host) and end to end by `mailbox-test` (`just _test-mailbox`, `test-mailbox-rpi4`): the client lends a table it carves for the Frames (300 under QEMU), is refused without `LEND`, sees an install failure into a too-small table hand nothing out, checks that every Frame's extent follows the one before and that they cover exactly the framebuffer's pages, and gets `already_handed_out` on a second call.
- [x] `mailbox_v1.set_led(boolean on)`: the mailbox component sends `SET_GPIO_STATE` for the activity LED's GPIO (`mailbox_impl::activity_led_pin`, from the board revision code: the firmware's expander pin 130 on the Raspberry Pi 3, SoC GPIO 42 on the Pi 4) so clients need not know the board; `SET_GPIO_STATE` stays refused through `property`. Exercised by `mailbox-test` on both boards (QEMU's firmware answers the tag without effect, so the pin numbers need hardware to confirm) and `drivers/mailbox/tests/tags.rs`.
- [x] Kickstart loads programs: a `[[component]]` manifest entry with `program = true` (plus `budget_ns`, `memory`, `video_memory`) is a driver without a device tree node (`libs/image-build`, `kernel/kickstart/src/drivers.rs`): one instance, no register pages, interrupts or DMA view, import chains starting from a `compatible` step, extra Threads declared with `driver_threads!` and started like a driver's. Exercised by `mailbox-test`, whose client is such a program with an extra Thread (`just _test-mailbox`, `test-mailbox-rpi4`).
- [x] Serial channel wiring in Kickstart (`kernel/kickstart/src/serial.rs`, `SerialChannelParts`): `create` carves the control page, data area and three `EventCount`s, `attach_driver` installs the driver's side at the slots `libserial-channel` fixes, `attach_client` maps the client's side at `CONTROL_VA`/`DATA_AREA_VA` and records its `EventCount`s in `DriverInit::serial`. A program with `serial = true` is attached to the first PL011 driver instance. `uart-test` attaches its boot-Thread client through `attach_driver`; the shell uses all three.
- [x] The shell (`userspace/shell/`): an EL0 program in the production image (`kernel/kickstart/image.toml`, `serial = true`), a command prompt on the PL011 serial channel with `help`, `led on`, `led off` (`mailbox_v1.set_led`), `draw` (not provided yet) and `end` (QEMU exit, or `power_v1.reset`). The command interpreter and line editor are a hardware-independent library with host tests (`userspace/shell/tests/commands.rs`); `just _test-shell` boots the production image under QEMU and types commands at it.
- [x] `[[resource]]` image entries (`libs/image-build`, `libimage::ResourceMapping`): a data file bundled as a read-only segment of each component naming it in `resources`, reported in `DriverInit::resources` (`DriverInit::resource(index)`). `kernel/kickstart/resources/font8x8.bin` is the first (the 8x8 console font, `shell::Font` with a host test); the shell reports it mapped at start and `just _test-shell` checks that. The component loader carves one L3 table per touched 2 MiB span, not for the whole range.
- [x] The display (now the compositor's, see the last entries): Kickstart gives a component importing `fb_v1` its second-level page table and four spare last-level tables (`DriverInit::map_window`, `FB_WINDOW_VA`); the shell's `draw` configures 1024x768, lends a table to `fb_v1.frames`, maps the Frames (device mapping), reads a painted pixel back, paints the static scene and releases a second Thread (`driver_threads!`) that animates lava blobs (`libs/graphics` `Lava`, integer-only) with a 40 ms frame timer. `libs/graphics` holds `Color`/`PixelOrder`, `Font`, `Surface`/`Painter` (rectangles, text) and `Lava`, with host tests (`libs/graphics/tests/graphics.rs`); `just _test-shell` checks the draw result and that the lamp thread draws frames 1 and 20. The boot table has 1024 entries (22-bit guards), Kickstart's page-table pool 16 per instance.
- [x] The old kernel-era mailbox, power, framebuffer and VideoCore files are gone from `libs/platform` (`raspberrypi/{fb,vc}.rs`, `device_driver/bcm/{power,mailbox,mailbox_refactor}.rs`); the `mailbox`, `power` and `fb` components replace them.
- [x] Meddle `channel <pages>;`: a `local` interface's per-client io-channel, provisioned by Kickstart after the data area (`libs/meddle`: lexer, parser, checks, type code, summary, generated `CHANNEL_PAGES` and `Bindings::channel`; `libs/meddle-runtime`: `ChannelArea`, `ImportRecord::channel_base`; `libs/device-driver`: `ExportedArea::channel_base`; `kernel/kickstart`: `PairArea`). Exercised by `libs/meddle/tests/meddle.rs`, `libs/meddle-runtime/tests/words.rs` and `just _test-usb`.
- [x] Callers are identified by badge: Kickstart badges each client's import key with the base of the pair's shared memory (`CopyDerive` from a key made in its own table, `CALL` only), `usb_hcd_v1` and `mailbox_v1` say `badged;`, and `DriverInit::area_for_badge` replaces the stack-pointer lookup (`calling_area` is removed). The controller records the owning client in each pipe. Exercised by the `areas` host tests, `just _test-usb`, `just _test-usb-core` and `just _test-mailbox`.
- [x] The compositor owns the display (`userspace/gui/compositor`, `userspace/libs/framebuffer`, `userspace/libs/compositor-core` damage, blitting and cursor): `compositor_v1` (`create_window` lends a table that receives the surface's 2 MiB Frames, `commit`, `set_title`, `move_window`, `raise`, `destroy`, `pixel_order`), `DriverInit::map_window` for importers of `fb_v1` and `compositor_v1` (`SURFACE_WINDOW_VA`), the shell drawing in a window. Exercised by `just _test-shell` (the lamp and the window's pixels reach the framebuffer), `just _test-compositor` (the background reaches it) and `just _test-compositor-host`.
- [x] Boot capacity for the larger production image (compositor and the USB stack): the boot Untyped is 128 MiB, `MAX_DRIVER_INSTANCES` is 12, and the boot table has 1024 entries with 22-bit guards (`libs/component-loader/src/keys.rs`).
- [x] SD card stack up to the card: `libs/block-channel` (a request queue on an io-channel: header record, block buffers, status written back; driver-side `shape`/`admit` checks), the `block_v1` interface (`channel 16`, `blocks`, `submitted`), and the EL0 `sdhost-bcm2835` component (SD card bring-up over a `Bus` trait, single-block programmed IO, a doorbell EventCount the `submitted` export rings). Kickstart now records `mmc` nodes' regions. Exercised by the `block_channel` and `sdhost` host tests and by `just _test-sd` up to the card, which QEMU leaves off SDHOST until its pins switch.
- [x] The EL0 `gpio-bcm2835` component owns the GPIO block and exports `gpio_v1.set_function` (input, output, ALT0 to ALT5) and `gpio_v1.set_pull` (off, down, up, through `GPPUD`/`GPPUDCLKn` with 1 µs steps); calls take turns on a turnstile. Kickstart copies each driver node's `pinctrl-0` pins, functions and pulls into `DriverInit::pins` (`libdevicetree::brcm_pins`), and `sdhost-bcm2835` imports `gpio_v1` and sets them up at start (GPIO 48 to 53 on ALT0). Exercised by the `gpio` and `devicetree` host tests and by `just _test-sd`, now in `just test`: the card comes up in QEMU, the marked blocks read, block 100 writes back, the malformed requests are refused, and the client pulls GPIO 26 up and off.
- [x] The SD card protocol is its own crate, `libs/sd-card` (with CMD18/CMD25), shared by `sdhost-bcm2835` and the new EL0 `sdhci` component: a standard SDHCI controller (`brcm,bcm2711-emmc2`, `brcm,bcm2712-sdhci`, and `brcm,bcm2835-sdhci` in `qemu` builds) in the production image, interrupt driven, moving blocks by ADMA2 through bounce pages where the controller has it and through the data port otherwise, several blocks per command with Auto CMD12; Kickstart hands drivers a node's fixed clock rate (`DriverInit::clock_hz`), and a `compatible` import step starts from the first enabled node. Exercised by the `sd_card`, `sdhci` and `devicetree` host tests and by `just _test-sdhci` and `_test-sdhci-rpi4` (data port only: QEMU's Arasan has no ADMA2; EMMC2 comes up polled without a card); not run on hardware.
- [x] Every instance of a component gets its own copy of its writable segments (`.data`) in fresh Frames; only read-only segments stay mapped in place over the retained image (`libs/component-loader/src/loader.rs`). Two instances of one driver used to share their initialized statics. Exercised by `just _test-board`, where both SDHCI instances log.
- [x] `sdhci` logs through `log_v1` (bring-up, a read of block 0 and its master boot record, panics and faults), with a finite interrupt wait per command (`sdhci::EVENT_MS`); the `board-test` image (PL011, log server, mailbox, `sdhci`) carries it to the UART on the boards (`just boot-board-test`). Exercised by `just _test-board` on raspi4b; not run on hardware.
- [x] PCIe root complex bring-up: Kickstart turns enabled host bridges' outbound windows into device Untypeds and hands a `pci_host = true` driver its windows, MSI controller and reset controller registers (`DriverInit::pci`, `libdevicetree::pci`, in a two-page init record); `libs/pci` enumerates buses and assigns BARs; the EL0 `pcie-brcmstb` component (`brcm,bcm2711-pcie`, `brcm,bcm2712-pcie`, with the BCM2712 MIP) brings the link up, logs the functions and their BARs and self-tests one software-raised MSI, bundled in `board-test`. Exercised by the `devicetree`, `pci` and `pcie` host tests; QEMU disables the PCIe node, so not run anywhere else yet.
- [x] Meddle multi-result (C2(a)): functions declare several results and exceptions several fields, up to five words after the outcome (`RESULT_WORDS`, `libs/meddle/src/check.rs`); generated traits and clients return a tuple, dispatch stores the words in order, and clients and `Exception::from_answer` reject nonzero words past them (`libs/meddle/src/emit.rs`, `libs/meddle-runtime`). Exercised by `just _test-meddle` (budgets, generated code for a two-result function, answer words).
